Cost code, budget & GL field map

stages 3–4, field by field

The Autodesk formattedCode is split on the dash; the pieces fan out to MRI, and PMJC_Map (the interface chart) resolves the entity, cost list and GL account to post against — the same cost code can map to a different account depending on phase.

0-01-010-O splits into → phase0 major01 minor010 cost code01-010 categoryO → map → GL acctby phase

The leading 0 is the phase (part 1). It is not part of the MRI cost code, which is only major-minor (01-010). Phase and cost code together pick the PMJC_Map row, so the phase decides which GL account the budget line posts to: the same 01-010 can post to a pre-development account in one phase and a WIP account in another.

composite keyAutodesk packs four values into one formattedCode string: phase-major-minor-category, e.g. 0-01-010-O. The integration cuts it on the dashes, and each part becomes its own field. Major + minor are also rejoined as the cost code. direct copyThe value is written to the MRI field unchanged, with no lookup or reformatting. E.g. major 01 → MajorCostCodePortion, originalAmount → OriginalAmount. PMJC_Map lookupAutodesk doesn't send these values. They come from the PMJC_Map row that matched: the entity, the cost list and the GL account the budget line posts to. match keyPhase + cost code together find the one PMJC_Map row to use (⚷ marks the key columns). If no row matches, the line can't be given a GL account. constant / job contextNot from the Autodesk budget. const is the same fixed value on every line (BudgetItem "1", DetailDescription "Original Budget"). context comes from the job being loaded (JobCode, BudgetType, Period, JobCostList).
